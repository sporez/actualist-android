# Actualist for Android (experimental)

An experimental native Android port of [Actualist](https://github.com/sporez/actualist),
a local-first client for [Actual Budget](https://actualbudget.org). Kotlin, Jetpack
Compose, Material 3 and SQLite.

**This is a personal engineering experiment, not a release.** It is not published,
has no production signing, and must not be pointed at a real budget. All tests and
the bundled demo budget use synthetic data only.

## Layout

| Module | Contents |
|---|---|
| `core/` | Pure Kotlin/JVM engine: Actual's HLC timestamps, merkle trie, protobuf sync wire format, AES-256-GCM encryption, the SQLite budget database with CRDT apply, an atomic local-write outbox and cell-level undo, envelope/tracking budget math and templates, transactions, splits, duplicate/merge, queries and saved filters, rules and category learning, schedules, reconciliation, import reconcile (CSV and SimpleFIN), account lifecycle and groups, the sync engine and the Actual server client. Runs in JVM unit tests and on Android through the bundled SQLite driver. |
| `app/` | Jetpack Compose + Material 3 Android app on top of `core`. |

The reference implementation and the exact commit this port follows are in
[`REFERENCE.md`](REFERENCE.md). Engineering status is in [`PROGRESS.md`](PROGRESS.md);
deliberate and inherited differences from Actual are in [`KNOWN_DIVERGENCES.md`](KNOWN_DIVERGENCES.md).

## Automation intents

With **Settings > Allow Automation** on, Tasker, Samsung Routines and other apps can send broadcasts
(permission `com.sporez.actualist.android.permission.AUTOMATION`) to `com.sporez.actualist.android` /
`.automation.AutomationReceiver`. Actions are prefixed `com.sporez.actualist.android.automation.`; extras are
strings. Everything is refused when automation is off or Sample Values is on. Writes are undoable, sync
when signed in, and refresh the widgets.

- Writes: `LOG_TRANSACTION`, `LOG_TRANSFER`, `UPDATE_TRANSACTION`, `CATEGORIZE_TRANSACTION`, `SET_CLEARED`,
  `DELETE_TRANSACTION`, `ASSIGN_BUDGET`, `ADD_TO_BUDGET`, `MOVE_MONEY`, `APPLY_TEMPLATES`, `SET_CARRYOVER`,
  `CREATE_PAYEE`, `CREATE_ACCOUNT`.
- Reads: `GET_BALANCES`, `GET_BUDGET_SUMMARY`, `GET_CATEGORY_BALANCE`, `GET_OVERSPENT`,
  `GET_UNCATEGORIZED_COUNT`, `GET_NET_WORTH`, `GET_CASH_FLOW`, `GET_RECENT_TRANSACTIONS`,
  `GET_UPCOMING_SCHEDULES`.
- Common extras: `amount` ("12.50"), `account`, `category`, `payee`, `notes`, `id` (a transaction id from
  `GET_RECENT_TRANSACTIONS`), `month` (`YYYY-MM`), `date` (`YYYY-MM-DD`).
- Result: an ordered broadcast's result code (OK or CANCELED) and data (the message), extras `ok`,
  `message`, the action's named values (amounts in minor units) and, for lists, `items`; or send
  `reply_package` to get the same extras back as a `...automation.RESULT` broadcast.

The full extras for every action are in the KDoc of `AutomationActions.kt`.

## Building

All builds and tests run in GitHub Actions; nothing Android-specific needs to be
installed locally.

- **Build and unit test** (`.github/workflows/build.yml`): every push. Builds the
  debug APK, runs the JVM tests, uploads the APK (`actualist-android-debug-apk`)
  and test reports.
- **Real Actual server** (`.github/workflows/real-server.yml`): on core changes. Runs a
  disposable `actualbudget/actual-server:26.10.0` service container with a synthetic
  password and drives login, new plain and encrypted budgets, ZIP import, download,
  two-device sync and conflicts against it; fails if those tests were skipped.
- **Android emulator tests** (`.github/workflows/emulator.yml`): manual dispatch
  at milestones (optional `test_filter` input for one class or method). Boots an API 34
  emulator, installs the APK, cold-launches it, runs the instrumentation/Compose UI
  suite (Compose v2 test API), including flows against a loopback Actual server inside
  the test process and against the same disposable real actual-server exposed on the
  device's loopback with `adb reverse`, kills the app process to check the selected
  budget reopens, and uploads screenshots, logcat and results (`emulator-results`).

With a local JDK 17 and Android SDK, `./gradlew :core:test :app:assembleDebug`
works as usual.
